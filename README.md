# 🌀 Minecraft Modpack Tools

Набор `.bat`-скриптов для разработки и поддержки модпака Minecraft.

Помогают автоматизировать рутину: список модов и конфигов, поиск дубликатов, проверка версий, очистка мусора, сравнение конфигов, быстрый доступ к папкам.

## 🖥 Требования

- **Windows 10 / 11** — для ANSI-цветов в консоли и корректной работы `chcp 65001`.
- На Windows 7/8 батники запустятся, но цвета могут отображаться как `←[93m` — работает всё равно.
- Никаких внешних зависимостей (Python, PowerShell, Node.js) — только встроенные `cmd.exe`, `dir`, `sort`, `findstr`.

## 📁 Структура папок

Батники ожидают примерно такую структуру в корне разработки:

```
MyModpack\
 ├─ mods\
 │   ├─ 00 - Optimization\
 │   │   ├─ sodium-fabric-0.5.11.jar
 │   │   └─ lithium-fabric-0.12.1.jar
 │   ├─ 01 - Util's\
 │   │   └─ ...
 │   ├─ 02 - Control's\
 │   ├─ 03 - Visual's\
 │   ├─ 04 - System's\
 │   ├─ 05 - Mob's\
 │   └─ 06 - Generation's\
 │
 ├─ Готовые\
 │   ├─ 00 - Optimization\
 │   │   ├─ sodium.toml
 │   │   └─ lithium.json
 │   └─ ...
 │
 └─ Сделать\
     ├─ 00 - Optimization\
     │   └─ ...
     └─ ...
```

- `mods\<категория>\*.jar` — используется в `mod_list.bat`, `find_duplicates.bat`, `mod_versions.bat`, `open_folders.bat`
- `Готовые\<категория>\*.{toml,json,json5,cfg,txt}` и `Сделать\<категория>\*.{...}` — используются в `config_list.bat`, `diff_configs.bat`

> Категории — это просто подпапки. Названия любые, сортировка идёт по алфавиту (`00 - ...`, `01 - ...` и т.д.).

## 🚀 Установка

1. Скачай `.bat`-файлы и положи рядом с корнем разработки (или в любую папку — большинство скриптов ищут `mods`, `Готовые`, `Сделать` рядом с собой).
2. Для `open_folders.bat` при **первом запуске** укажи путь к корню — он сохранится в `open_folders.cfg` рядом с батником.
3. Запускай двойным кликом.

> Если нужно, чтобы окно не мелькало — сделай `.vbs`-обёртку (см. [FAQ](#-faq)).

## 🧰 Батники

### 1. `mod_list.bat`

Красиво выводит список `.jar` из `mods\<категория>\` и пишет в **`mod_list.txt`**.

**Что делает:**
- Читает подпапки в `mods\`
- В каждой — список `.jar` с нумерацией
- Пишет всё в `mod_list.txt` рядом с батником
- Внизу — сводка: количество категорий и модов

**Пример вывода `mod_list.txt`:**
```
╔══════════════════════════════════════════════════════════╗
║              СПИСОК МОДОВ ПО КАТЕГОРИЯМ                  ║
╚══════════════════════════════════════════════════════════╝

┌─ [00 - Optimization]  (2 шт.)
│
│   • sodium-fabric-0.5.11.jar
│   • lithium-fabric-0.12.1.jar
└──────────────────────────────────────────────────────────
```

**Настройки внутри:** `MODS_DIR`, `OUT_FILE` (в начале батника).

### 2. `config_list.bat`

Список конфигов из `Готовые\` и `Сделать\`, сгруппированный по категориям. Пишет в **`config_list.txt`**.

**Что делает:**
- Читает `Готовые\<категория>\*.{toml,json,json5,cfg,txt}`
- Читает `Сделать\<категория>\*.{toml,json,json5,cfg,txt}`
- Выводит сначала блок **СДЕЛАТЬ**, потом **ГОТОВЫЕ**
- Пустые категории не выводятся
- Внизу — сводка по каждому блоку

**Пример вывода `config_list.txt`:**
```
╔══════════════════════════════════════════════════════════╗
║               СПИСОК КОНФИГОВ ПО КАТЕГОРИЯМ               ║
╚══════════════════════════════════════════════════════════╝

════════════════════════════════════════════════════════════
  [ СДЕЛАТЬ ]
════════════════════════════════════════════════════════════

┌─ [00 - Optimization]  (2 шт.)
│
│   • sodium.toml
│   • lithium.json
└──────────────────────────────────────────────────────────

════════════════════════════════════════════════════════════
  [ ГОТОВЫЕ ]
════════════════════════════════════════════════════════════
...
```

### 3. `diff_configs.bat`

Сравнивает конфиги в `Сделать\` и `Готовые\`. Пишет отчёт в **`config_diff.txt`**.

**Что показывает:**
- `+` — файл есть только в `Сделать` (не перенесён)
- `-` — файл есть только в `Готовые` (уже отработан / удалён)
- `~` — файл есть в обеих, но отличается по размеру или дате

**Пример вывода `config_diff.txt`:**
```
┌─ [00 - Optimization]
│
│  [ТОЛЬКО В СДЕЛАТЬ]
│    + sodium.toml
│
│  [ТОЛЬКО В ГОТОВЫЕ]
│    - lithium.json
│
│  [ОТЛИЧАЮТСЯ]
│    ~ embeddium.toml [1204 -> 1180 байт]
│    ~ ferritecore.json [дата: 15.09.2026 10:22 -> 17.09.2026 18:40]
└──────────────────────────────────────────────────────────
```

### 4. `clean.bat`

Чистит мусор: `logs`, `crash-reports`, `.mixin.out`, `local`, `*.bak`, `*.tmp`, `*.log`.

**Что чистит:**
| Путь | Что делает |
|------|-----------|
| `logs\` | Полностью очищает содержимое |
| `crash-reports\` | Полностью очищает содержимое |
| `.mixin.out\` | Полностью очищает содержимое |
| `local\` | Полностью очищает содержимое |
| `config\*.bak`, `config\*.tmp` | Рекурсивно |
| `Сделать\*\*.bak`, `Сделать\*\*.tmp` | Рекурсивно |
| `Готовые\*\*.bak`, `Готовые\*\*.tmp` | Рекурсивно |
| `*.log` в корне | Рекурсивно |

**Особенности:**
- Перед запуском **спрашивает подтверждение** (`y/n`).
- Папки оставляет, чистит только содержимое.
- В конце пишет: сколько файлов удалено.

### 5. `find_duplicates.bat`

Ищет дубликаты `.jar` в `mods\<категория>\`. Пишет в **`duplicates.txt`**.

**Три блока:**
1. **[1] Точные дубликаты** — одинаковое имя файла в разных категориях
2. **[2] Похожие моды** — одно имя мода, разные версии (например, `sodium-fabric-0.5.8.jar` и `sodium-fabric-0.5.11.jar`)
3. **[3] Одинаковый размер** — файлы одного размера (косвенный признак копии)

**Пример вывода `duplicates.txt`:**
```
[2] ПОХОЖИЕ МОДЫ (одно имя, разные версии)
┌─ [sodium]  (2 шт.)
│   • 00 - Optimization/sodium-fabric-0.5.8.jar
│   • 03 - Visual's/sodium-fabric-0.5.11.jar
└──────────────────────────────────────────────────────────
```

**Нормализация имён:** убирает загрузчик (`fabric`/`forge`/`neoforge`/`quilt`) и версию, оставляя чистое имя мода.

### 6. `mod_versions.bat`

Собирает версии модов из имён `.jar` в `mods\<категория>\`. Пишет в **`mod_versions.txt`**.

**Пример вывода:**
```
┌─ [00 - Optimization]
│
│   ferritecore              6.0.1          ferritecore-6.0.1-forge.jar
│   lithium                  0.12.1         lithium-fabric-0.12.1.jar
│   sodium                   0.5.11         sodium-fabric-0.5.11.jar
│
└─ Всего: 3 шт.
──────────────────────────────────────────────────────────
```

**Как парсит:**
- Имя мода = токены до первого числового
- Версия = первый токен, начинающийся с цифры (или `mc1.20.1`)

---

### 7. `open_folders.bat`

Открывает `mods\` и `config\` в проводнике одним запуском. Закрывается автоматически.

**Как работает:**
1. **Первый запуск** — спрашивает путь к корню разработки, сохраняет в `open_folders.cfg`.
2. **Дальше** — сразу открывает обе папки и закрывается.

**Файл `open_folders.cfg`** — одна строка с путём. Удалить = сбросить.

## 🎨 Цвета и кодировка

Все батники используют:
- `chcp 65001` — UTF-8, чтобы русские буквы в путях и тексте отображались корректно.
- ANSI-escape (`ESC[93m` и т.п.) — цвета в консоли.

Чтобы цвета работали, нужна **Windows 10 (1511+) или Windows 11**. На старых версиях вместо цвета будет мусор вроде `←[93m` — это не критично, всё работает.

## ❓ FAQ

**Q: Файл `open_folders.cfg` удалил, а батник всё равно спрашивает путь — почему?**  
A: Это нормально. `open_folders.bat` при отсутствии cfg всегда переспрашивает путь. Так задумано.

**Q: Батники в другой папке, а `mods` — в другом месте. Что делать?**  
A: Положи батники в корень разработки (рядом с `mods`, `Готовые`, `Сделать`). Либо исправь `MODS_DIR` / `DONE_DIR` / `TODO_DIR` в начале нужного батника.

**Q: Хочу, чтобы окно консоли не мелькало.**  
A: Создай рядом `.vbs`-файл:
```vbs
Set WshShell = CreateObject("WScript.Shell")
WshShell.Run chr(34) & "open_folders.bat" & Chr(34), 0
Set WshShell = Nothing
```
И запускай `.vbs` — батник отработает в фоне.

**Q: У меня Windows 7, цвета показываются как `←[93m`.**  
A: Это ANSI-коды, которые старые консоли не понимают. Открой батник, найди блок `for /f %%a in ('echo prompt $E ^| cmd')` и закомментируй (`::`), либо замени `ESC` на пусто. Всё остальное продолжит работать.

**Q: Как добавить новое расширение конфигов в `config_list.bat` / `diff_configs.bat`?**  
A: Найди блок с `for %%E in (toml json json5 cfg txt)` и добавь нужное расширение через пробел, например `toml json json5 cfg txt yaml yml properties`.

**Q: `diff_configs.bat` сравнивает только по размеру и дате — можно побайтово?**  
A: Пока нет. Побайтовое сравнение (`fc /b`) сильно медленнее и не всегда нужно. Если размер + дата совпали, файлы считаются идентичными.

**Q: Будут ли батники работать на сервере / другом ПК?**  
A: Да, зависимостей нет. Убедись только, что в `cmd.exe` установлен `chcp 65001` (обычно да) и есть права на запись в папку (для `*.txt`-отчётов).
